PROJECT: SILA ME
FEATURE: ADVANCED BACKEND INVOICE OCR + MOBILE AUTO-FALLBACK + CLOUD OCR CONFIGURATION

OBJECTIVE

Build a highly efficient BACKEND ADVANCED INVOICE OCR capability for
SILA ME.

The Mobile OCR remains the FAST first-level OCR.

The new backend OCR becomes the HIGH-ACCURACY / DETAILED extraction
engine.

============================================================
1. CORE DESIGN
============================================================

Implement TWO OCR levels.

LEVEL 1:

MOBILE BASIC OCR

Purpose:
speed.

Extract primarily:

Supplier Name
Invoice Number
PO Number
Invoice Amount

plus existing basic fields where possible.

LEVEL 2:

BACKEND ADVANCED OCR

Purpose:

high-quality detailed invoice extraction.

It receives the actual scanned PDF and performs:

PDF analysis
OCR
layout/text analysis
invoice field extraction
line-item extraction
normalization
candidate scoring
confidence
validation
structured invoice output.

Backend Advanced OCR is the authoritative extraction service.

============================================================
2. FLOW
============================================================

Normal flow:

Mobile Scan
→ PDF Generated
→ Mobile Basic OCR
→ Evaluate Basic OCR Result.

If sufficient:

show Basic Review immediately.

If insufficient AND Cloud configuration enables automatic backend
fallback:

upload/pass the already-generated scanned PDF to:

BACKEND ADVANCED OCR.

Backend extracts detailed invoice.

Return extraction.

Populate Mobile Review.

If automatic fallback disabled:

show Mobile result and allow:

RE-READ INVOICE.

RE-READ INVOICE must call backend Advanced OCR.

============================================================
3. DO NOT RECREATE PDF
============================================================

Use the EXACT scanned PDF already generated by Mobile.

Do not:

rescan
recreate pages
take screenshots
generate another PDF.

The PDF sent to backend OCR must be the same document that will
ultimately be stored against the invoice/document.

============================================================
4. BACKEND OCR API
============================================================

Create/reuse a versioned endpoint.

Preferred:

POST /api/v1/invoices/advanced-extract

multipart/form-data.

Input:

file = scanned invoice PDF

plus only required safe business context.

If a SILA document already exists, also support:

POST /api/v1/documents/{documentId}/advanced-extract

This should process the authoritative stored document rather than
requiring the PDF to be uploaded again.

Prefer documentId-based processing once document exists.

============================================================
17. FINANCIAL RECONCILIATION
============================================================

Perform mathematical validation where enough fields exist.

Examples:

Net + Tax = Gross

Subtotal - Discount + Charges + Tax = Gross

Sum(Line Net) ≈ Invoice Net

Sum(Line Tax) ≈ Invoice Tax

Sum(Line Gross) ≈ Invoice Gross.

Allow configurable rounding tolerance.

Do not change extracted values merely to force reconciliation.

Instead return validation flags.

============================================================
27. IMPORTANT — MOBILE MUST NOT DECIDE POLICY
============================================================

Do not hardcode fallback policy only in React Native.
