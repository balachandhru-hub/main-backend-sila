==================================================
SILA ME — GLOBAL GUI / UX DESIGN SYSTEM
APPLIES TO CLOUD + MOBILE
==================================================

IMPORTANT:

The attached SILA ME logo is the visual source of truth.

The Cloud and Mobile applications must look like ONE product family.

Do NOT create separate visual identities for Cloud and Mobile.

The design should be:

- clean
- white
- premium
- modern
- enterprise
- hospitality-oriented
- simple
- spacious
- mobile friendly
- consistent

The SILA ME logo must drive the primary color palette.

The logo contains a light-blue / blue visual identity.

Extract/sample the actual primary colors from the supplied logo instead of inventing unrelated colors.

Do NOT change the logo colors.


==================================================
1. GLOBAL BACKGROUND
==================================================

ALL application pages must use:

WHITE background.

Primary page background:

#FFFFFF

Do NOT use:

- gray full-page backgrounds
- blue full-page backgrounds
- gradients as page backgrounds
- dark application backgrounds
- colored panels covering large portions of pages

Cloud:

body background = white

Mobile:

screen background = white

The entire product should feel bright and clean.


==================================================
2. PRIMARY COLOR SYSTEM
==================================================

Use the attached SILA ME logo to derive the exact brand blue.

Create design tokens such as:

--sila-primary
--sila-primary-light
--sila-primary-dark
--sila-border
--sila-text
--sila-text-secondary
--sila-background
--sila-surface
--sila-error
--sila-success
--sila-warning

Do not hardcode random blue shades throughout components.

Use ONE centralized theme.

Suggested visual intent:

Primary:
SILA logo light blue

Primary Dark:
slightly darker version of logo blue for readable text/buttons

Primary Light:
very pale logo-blue background for selected/hover states

Border:
logo blue with suitable opacity

Page Background:
white

Surface/Card:
white

Main Text:
dark navy / dark charcoal

Secondary Text:
neutral gray

Use the actual logo color as the reference.


==================================================
3. COLOR ACCESSIBILITY
==================================================

Because the SILA logo uses light blue:

DO NOT use very light-blue text on white where readability becomes poor.

Use:

dark navy / charcoal for normal text

Use logo blue for:

- active menu
- links
- borders
- icons
- highlights
- selected states
- primary actions where contrast is sufficient

If the exact logo blue is too light for a primary button background:

use a slightly darker derived brand-blue for button background

while keeping the logo itself unchanged.

Button text must have proper visual contrast.


==================================================
4. LOGO USAGE
==================================================

Use the attached SILA ME logo.

Cloud login:
logo centered above application name.

Cloud navigation:
logo top-left.

Mobile login:
logo centered near top.

Mobile Home:
logo or compact SILA ME brand mark in header.

Do not:

- stretch logo
- recolor logo
- crop logo badly
- place logo on conflicting colored backgrounds
- create a new logo
- add effects/shadows to the logo
- distort aspect ratio

Use transparent/white logo background as appropriate.


==================================================
5. BORDER DESIGN
==================================================

Borders should follow the SILA blue identity.

Use thin blue or light-blue borders.

Typical:

1px solid brand blue with reduced opacity

Examples of components requiring blue-border treatment:

- login form
- input fields
- cards
- data containers
- modal dialogs
- menus
- dropdowns
- search controls
- filter boxes

Avoid strong black borders.

Avoid heavy dark gray borders.


==================================================
6. CARDS
==================================================

Cards must be:

background: white

border:
thin SILA blue/light-blue

border radius:
10–14px

shadow:
very subtle only

Do not create heavy floating shadows.

Cloud example:

┌──────────────────────────────┐
│                              │
│       White Card             │
│                              │
└──────────────────────────────┘
 Light SILA Blue Border

Cards should feel clean rather than decorative.


==================================================
7. INPUT FIELDS
==================================================

Input fields:

background:
white

text:
dark navy/charcoal

border:
light SILA blue

border radius:
8–10px

Normal:

light blue border

Focus:

stronger SILA blue border

Optional subtle focus ring:

logo blue at low opacity

Placeholder:

medium gray

Error:

red border + error text

Do NOT make input backgrounds gray.


==================================================
8. PRIMARY BUTTONS
==================================================

Primary actions such as:

Login
Save
Continue
Confirm
Submit

Use:

background:
brand blue or darker accessible SILA blue

text:
white

border:
same blue

border radius:
8–10px

Hover on web:

slightly darker blue

Pressed on mobile:

slightly darker blue / reduced opacity

Disabled:

pale blue-gray background
muted text
no aggressive contrast


==================================================
9. SECONDARY BUTTONS
==================================================

Secondary actions:

background:
white

text:
SILA blue

border:
SILA blue

Examples:

Cancel
Back
Edit
View

Hover:

very light SILA-blue background.

Do not use gray-filled secondary buttons unless functionally required.


==================================================
10. DESTRUCTIVE BUTTONS
==================================================

Only destructive actions should use red.

Examples:

Delete
Remove
Deactivate

Do not use red for normal navigation/actions.


==================================================
11. TEXT SYSTEM
==================================================

Main heading:

dark navy / near-black

Secondary headings:

dark navy

Body:

dark charcoal

Supporting text:

neutral medium gray

Links:

SILA blue

Avoid light blue for paragraph text.

Suggested hierarchy:

Page title:
28–32px Cloud
24–28px Mobile

Section title:
20–24px

Card title:
16–18px

Body:
14–16px

Caption:
12–13px

Maintain readable line-height.


==================================================
12. TYPOGRAPHY
==================================================

Use one clean modern sans-serif family.

Preferred:

Inter

If unavailable use:

system UI stack

Cloud and Mobile typography should feel consistent.

Avoid decorative fonts.


==================================================

WHITE background.

thin SILA blue/light-blue.

SILA ME logo

==================================================
18. MOBILE HEADER
==================================================

Mobile screens should use:

SILA blue bottom border or subtle divider.

Page title:

dark navy

Icons:

SILA blue / dark navy.

Do not use an oversized blue app bar.


==================================================
19. MOBILE BOTTOM NAVIGATION
==================================================

When bottom navigation is added later:

background:
WHITE

light SILA blue

gray text/icon

SILA blue icon
SILA blue label

Do not use a solid-blue bottom navigation background.


==================================================
20. ICONOGRAPHY
==================================================

Use one consistent icon library.

Icons should be:

simple
outlined where suitable
modern
clean

Default:

dark navy / gray

Interactive/active:

SILA blue

Avoid multiple icon styles.


==================================================
21. MENU BEHAVIOUR — CLOUD
==================================================

Menus must support:

hover

selected state

keyboard focus

active route indication

tooltips where icons are not obvious

Desktop sidebar may collapse later.

For Phase 0 keep navigation minimal.

Do not overbuild the menu.


==================================================
22. MENU BEHAVIOUR — MOBILE
==================================================

Mobile interactions must be touch-first.

Minimum practical touch target:

44px approximately.

Buttons must not be too close together.

Do not reproduce desktop sidebar navigation on mobile.

Use mobile-native navigation patterns.


==================================================
23. RESPONSIVENESS — CLOUD
==================================================

Cloud application should support:

desktop
laptop
tablet

The Phase 0 Login and Dashboard must render correctly at:

1920px
1440px
1280px
1024px
768px

Avoid fixed-width layouts that break.


==================================================
24. RESPONSIVENESS — MOBILE
==================================================

Test at least common widths around:

320px
360px
390px
414px
430px

Avoid:

horizontal scrolling
clipped buttons
text overflow
logo overflow


==================================================
25. STATUS INDICATORS
==================================================

Success:

green icon/text with very pale green surface if required.

Warning:

amber.

Error:

red.

Information:

SILA blue.

Do not use excessive colored containers.


==================================================
26. LOADING BEHAVIOUR
==================================================

Both apps need consistent loading states.

For API activity:

show small spinner/progress indication.

Disable action button while submitting.

Example Login:

Normal:

Sign In

During request:

spinner + Signing in...

Prevent multiple submissions.

Do not show blank screen while API request runs.


==================================================
27. ERROR BEHAVIOUR
==================================================

Login errors should display directly below or above the login controls.

Example:

Invalid email or password.

Use:

small red icon
red text
very pale red background if required

Do not use browser alerts.

Do not expose:

stack traces
HTTP internals
database errors
exception text


==================================================
28. SUCCESS BEHAVIOUR
==================================================

Use small inline confirmation/toast where appropriate.

Example:

Profile updated successfully.

Do not use modal dialogs for every successful action.


==================================================
29. EMPTY STATES
==================================================

Future empty screens should not appear broken.

Example:

No records available yet.

Provide:

simple icon
short text
optional action

Use white background.

Do not add decorative stock illustrations unless approved.


==================================================
30. MODALS
==================================================

Cloud:

white modal
blue border
subtle shadow
dark heading
white background

Mobile:

prefer proper mobile sheet/screen patterns where appropriate.

Avoid overly large modal windows.
