PROJECT: SILA ME

IMPLEMENT BASIC OCR FALLBACK FOR EXPO GO / REPLIT TESTING.

CURRENT STATUS:

Native OCR implementation exists using ML Kit.

However:

RNMLKitTextRecognition is unavailable in Expo Go.

Replit currently serves:

exp://...expo.sisko.replit.dev

This is an Expo Go bundle and NOT a custom Development Build.

DO NOT REMOVE ML KIT.

DO NOT replace the native OCR implementation.

Instead implement an automatic BASIC OCR provider strategy.

==================================================
1. REQUIRED ARCHITECTURE
==================================================

Basic invoice extraction must work in BOTH environments.

PRODUCTION / DEVELOPMENT BUILD:

Processed Scan Images
→ Native ML Kit OCR
→ Basic Invoice Parser
→ Basic Invoice Fields

EXPO GO / REPLIT:

Processed Scan Images / Generated PDF
→ Existing SILA ME .NET API
→ Built-In OCR
→ Basic Invoice Parser
→ Basic Invoice Fields

The user should see the SAME Invoice Basic Review screen regardless
of which OCR provider was used.

==================================================
2. PROVIDER STRATEGY
==================================================

Create/use:

IBasicOcrProvider

Implement:

NativeMlKitBasicOcrProvider

BackendBasicOcrProvider

Create:

BasicOcrProviderResolver

Concept:

if native ML Kit module is available:

    use NativeMlKitBasicOcrProvider

else:

    use BackendBasicOcrProvider

Do NOT detect only:

Platform.OS

because iOS/Android Expo Go still does not contain ML Kit.

Detect whether the native module is actually available.

==================================================
3. NEVER CRASH WHEN ML KIT IS MISSING
==================================================

Current condition:

RNMLKitTextRecognition unavailable

must NOT cause:

OCR failure
blank screen
runtime exception
unhandled promise rejection.

Instead:

ML Kit unavailable
→ automatically select BackendBasicOcrProvider.

Development log:

[BasicOCR] Native ML Kit unavailable
[BasicOCR] Using backend fallback

==================================================
4. BACKEND BASIC OCR ENDPOINT
==================================================

Use the EXISTING SILA ME .NET backend.

Do not create another service/application.

Add/reuse an authenticated endpoint such as:

POST /api/v1/documents/basic-extract

Input:

multipart/form-data

Preferred:

document = generated PDF

OR, if the existing built-in OCR performs better on images:

pages = processed scanner images

Include existing organization/operating-unit context as required by
current SILA ME authorization.

Use the EXISTING authenticated Mobile API client.
