PROJECT: SILA ME

FEATURE PHASE:
INVOICE SCANNER + INVOICE DATA EXTRACTION + PO MATCHING + GRN POSTING

OBJECTIVE:
Add the first complete operational transaction feature to the existing SILA ME platform.

Existing architecture must remain:

- SILA ME Cloud — React / TypeScript / Vite
- SILA ME Mobile — Expo / React Native / TypeScript
- SILA ME API — ASP.NET Core Web API / C#
- PostgreSQL
- Entity Framework Core
- Existing organization/access-control foundation
- Existing Cloud cookie authentication
- Existing Mobile bearer-token authentication
- Existing shared user/organization/operating-unit access model

DO NOT rebuild the foundation.

DO NOT change the authentication architecture.

DO NOT create another backend.

Use the existing .NET backend and PostgreSQL database.

==================================================
1. BUSINESS OBJECTIVE
==================================================

Implement this end-to-end flow:

Store Manager
→ Open SILA ME Mobile
→ Scan Invoice
→ Upload invoice images/PDF
→ Backend processes document
→ Extract invoice text/data
→ Identify supplier
→ Extract PO number
→ Extract invoice header
→ Extract invoice line items
→ Match invoice to PO
→ Match invoice lines to PO lines
→ Store Manager reviews data
→ Store Manager confirms physical received quantities
→ Validate against PO
→ Review GRN
→ Post GRN
→ Update PO received/open quantities
→ Update local inventory
→ Create inventory ledger
→ Display GRN in Mobile
→ Display Invoice and GRN in Cloud

IMPORTANT:

INVOICE QUANTITY IS NOT AUTOMATICALLY THE GRN QUANTITY.

Invoice scanner may extract:

Invoice Qty = 50 KG

But Store Manager may physically receive:

48 KG

GRN must post:

48 KG

NOT:

50 KG

Physical received quantity confirmed by the Store Manager is authoritative for GRN posting.

3. EXTRACTION STRATEGY
==================================================

There are three document scenarios.

CASE A:
Digital PDF with embedded text.

Do not OCR unnecessarily.

Use PDF text extraction first.

CASE B:
Scanned PDF.

Perform OCR page-by-page.

CASE C:
Mobile camera image.

Perform OCR.

Create these abstractions:

IDocumentTextExtractor

IPdfTextExtractor

IOcrProvider

IInvoiceExtractionService

IInvoiceNormalizationService

Suggested flow:

Document
→ Detect document type
→ Detect embedded text
→ Extract text directly OR OCR
→ Normalize extracted text
→ Produce structured Invoice DTO

29. PO MATCHING
==================================================

PO matching priority:

1. Exact PO number extracted from invoice
2. User-entered PO number
3. Supplier + operating unit + open PO
4. Supplier + invoice line materials
5. Manual PO selection

If exact match:

load PO automatically but still display for confirmation.

If multiple candidates:

display candidate PO list.
