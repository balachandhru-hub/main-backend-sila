PROJECT: SILA ME MOBILE

TASK:
REWORK THE MOBILE DOCUMENT SCANNER TO PRODUCE HIGH-QUALITY MULTI-PAGE PDFS FROM THE ORIGINAL CAPTURED PAGE IMAGES.

CURRENT PROBLEM:

The app currently allows multiple pages, but PDF output quality is poor.

It appears the PDF is being generated from a screenshot/render of the page-review screen that contains multiple invoice thumbnails/images.

THIS IS WRONG.

The generated PDF must NOT contain:

- screenshots of the mobile UI
- page-review screen
- thumbnails
- buttons
- margins from the React Native view
- multiple document pages flattened into one screenshot

The generated PDF must contain the ACTUAL SCANNED DOCUMENT PAGES.

==================================================
1. TARGET EXPERIENCE
==================================================

The scanner should behave similar to the native iPhone document scanner.

Flow:

Open Scanner
→ Scan Page 1
→ Detect/correct document
→ Store original processed Page 1 image
→ Add Page
→ Scan Page 2
→ Store original processed Page 2 image
→ Add Page
→ Scan Page 3
→ Review thumbnails
→ Done / Create PDF
→ Generate ONE PDF from Page 1 + Page 2 + Page 3 source images
→ PDF immediately available
→ Run basic OCR
→ Display invoice basic details
→ Save

Do NOT take any screenshot of a React Native screen to create the PDF.

==================================================
2. CRITICAL PDF RULE
==================================================

PDF generation input must be:

ScanSession.pages[].processedImageUri

NOT:

ViewShot
Screenshot
React Native component capture
thumbnail image
combined preview image

Each source image becomes exactly one PDF page.

Example:

processed-page-001.jpg
→ PDF page 1

processed-page-002.jpg
→ PDF page 2

processed-page-003.jpg
→ PDF page 3

Result:

invoice-<scanSessionId>.pdf

==================================================
3. REMOVE WRONG IMPLEMENTATION
==================================================

Search the existing implementation for any use of:

react-native-view-shot
captureRef
captureScreen
ViewShot
screenshot
DOM canvas capture
html-to-image
screen snapshot

being used to create invoice PDF pages.

If any such mechanism is used for PDF generation:

REMOVE IT FROM THE PDF GENERATION PATH.

It may remain for unrelated UI uses only.

==================================================
4. PAGE DATA MODEL
==================================================

Each scanned page must be represented independently.

Use something like:

type ScanPage = {
  id: string;
  pageNumber: number;

  originalImageUri: string;
  processedImageUri: string;
  thumbnailUri?: string;

  width: number;
  height: number;

  rotation: 0 | 90 | 180 | 270;

  crop?: {
    topLeft: Point;
    topRight: Point;
    bottomLeft: Point;
    bottomRight: Point;
  };

  ocrText?: string;

  createdAt: string;
};

IMPORTANT:

thumbnailUri is ONLY for screen preview.

PDF generation must use processedImageUri.

Never use thumbnailUri to build PDF.

==================================================
5. IMAGE QUALITY
==================================================

Captured invoice pages must remain high quality.

Target:

long edge approximately 2000–3000 px after processing where practical.

Do not downscale to thumbnail size.

JPEG quality:

approximately 0.85–0.95.

Do not repeatedly JPEG-compress the same image.

Preferred:

camera capture
→ one processing pass
→ final processed page image
→ PDF

Avoid:

capture
→ compress
→ preview screenshot
→ compress again
→ PDF

==================================================
6. CAMERA CAPTURE SETTINGS
==================================================

Use the highest practical document-quality camera output.

Do not use thumbnail/preview resolution as the captured image.

Where camera API allows:

use high picture quality.

Correct EXIF orientation.

Store actual captured dimensions.

Do not resize solely based on mobile screen dimensions.

==================================================
7. DOCUMENT PROCESSING
==================================================

For each page after capture:

1. Correct orientation
2. Detect/correct crop where supported
3. Deskew/perspective correct where available
4. Improve contrast moderately
5. Preserve readable text
6. Save processed document image separately

Do not add UI borders/background to the processed image.

The output should contain DOCUMENT ONLY.

==================================================
8. AUTO DOCUMENT EDGE DETECTION
==================================================

If current scanner package supports document edge detection:

ENABLE IT.

Preferred scanner experience:

camera detects rectangular document
→ highlights edges
→ user captures
→ automatic perspective correction

Allow manual crop correction if available.

If current Expo camera implementation cannot provide this properly, evaluate a maintained native document-scanner module.

Do not fake document detection using screenshot cropping.

==================================================
12. PDF GENERATION
==================================================

Implement a true image-to-PDF generator.

Do NOT use HTML rendering of the screen.

For every ScanPage:

1. Read processedImageUri
2. Determine image width/height
3. Create one PDF page
4. Preserve document aspect ratio
5. Fit page without clipping
6. Embed high-quality image
7. Continue next page

Generate:

application/pdf

==================================================
13. PDF PAGE SIZE
==================================================

Preserve natural document orientation.

Portrait source:
portrait PDF page

Landscape source:
landscape PDF page

Prefer A4 fitting if required by library, but preserve aspect ratio.

Do not stretch invoice image.

Do not crop text at edges.

14. IMAGE TO PDF OPTIONS
==================================================

Inspect the current project and choose the best maintained solution.

Possible implementation approaches:

- native image-to-PDF package

Preference:

If the scanner SDK itself can generate a proper scanned PDF from original captures, use that.

Otherwise generate with pdf-lib/native image-to-PDF package.

DO NOT generate PDF through a rendered HTML/React screen.
