==================================================
1. REQUIRED MOBILE BASIC OCR FIELDS
==================================================

Mobile must automatically attempt to extract:

1. Supplier Name
2. Supplier TRN
3. Supplier Invoice Number
4. Invoice Date
5. Purchase Order Number
6. Invoice Gross Amount
7. Currency

These values must be shown on the Invoice Basic Review screen.

OCR is an assistance mechanism.

If confidence is low or a field is not found:

DO NOT invent a value.

Leave it blank and allow the user to enter/correct it.

==================================================
2. IMPORTANT ARCHITECTURE
==================================================

BASIC OCR must happen ON THE MOBILE SCAN FLOW.

It must NOT require:

- Cloud
- External OCR agent
- External LLM
- OpenAI
- backend full extraction
- invoice_ext_data
- user pressing Save first

The phone must perform basic OCR immediately after scanning/PDF creation.

Backend full invoice extraction remains a separate process AFTER Save.

==================================================
3. OCR THE PAGE IMAGES — NOT THE PDF PREVIEW
==================================================

OCR source MUST be:

ScanPage.processedImageUri

For every scanned page:

processedImageUri
→ OCR
→ page OCR text

DO NOT OCR:

thumbnailUri

PDF viewer

screen screenshot

review screen

HTML

compressed thumbnail.

The high-quality processed scanner image is the OCR input.

13. SUPPLIER TRN EXTRACTION
==================================================

For UAE invoices specifically recognize labels such as:

TRN
Tax Registration Number
VAT Registration Number
VAT Reg No
Tax Reg No

Typical UAE TRN is 15 digits.

Example pattern concept:

\b\d{15}\b

BUT:

do not simply take the first 15-digit number blindly.

Prefer a 15-digit number located near:

TRN
VAT
Tax Registration

Normalize spaces/hyphens where OCR inserted them.

==================================================
19. SUPPLIER NAME — IMPORTANT
==================================================

Supplier Name is harder than regex fields.

Use deterministic invoice-layout heuristics.

Prefer:

top portion of Page 1

business name near logo/header

name located near supplier TRN/address

"Supplier"
"Vendor"
"From"

Avoid extracting:

customer/buyer name

Ship To

Bill To

Sold To.

If uncertain:

leave Supplier Name blank rather than selecting the buyer.

==================================================

Header fields should normally prioritize Page 1:

==================================================
21. FIELD SCORING
==================================================

Do not simply use the first regex match.

Score candidates.

Example factors:

label proximity

same line as label

next line after label

page position

Page 1 priority

total-page priority

valid format

duplicate consistency.

Select highest-confidence candidate.

==================================================
22. OCR NORMALIZATION
==================================================

Before parsing:

normalize Unicode

normalize whitespace

retain line breaks

collapse repeated spaces

normalize common OCR separators

BUT:

do not destroy line structure.

Invoice layout parsing depends on line relationships.

Keep:

rawText

and:

normalizedText

separately.

==================================================
23. COMMON OCR CHARACTER ERRORS
==================================================

Handle common OCR confusion carefully:

O vs 0

I vs 1

S vs 5

B vs 8

Only normalize when field context makes it safe.

Example:

so:

O → 0

may be appropriate.

Do NOT globally change supplier names.
