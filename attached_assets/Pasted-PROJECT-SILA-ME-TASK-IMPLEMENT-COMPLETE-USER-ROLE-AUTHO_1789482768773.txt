2. THREE SEPARATE SECURITY CONCEPTS
============================================================

Never mix:

APPLICATION ACCESS

ROLE

SCOPE.

APPLICATION ACCESS answers:

Where can the user login?

CLOUD
MOBILE
BOTH

ROLE answers:

What does the user normally do?

SCOPE answers:

Where can the user do it?

Example:

User:
John

System:
MOBILE

Role:
RECEIVING_OPERATOR

Organization:
ABC Hospitality

Property:
Property A

Store:
Main Store

Authorization:
POST_GRN

Therefore John can post GRNs only inside his authorized scope.

============================================================
25. EXPLICIT USER DENY
============================================================

User DENY overrides all role grants.

Example:

Role A grants POST_GRN.

Role B also grants POST_GRN.

User override:

DENY POST_GRN.

Effective:

POST_GRN = DENIED.

Use a proper backend-driven Microsoft authorization/validation flow.

Conceptually:

SILA ME Cloud
      ↓
CONNECT MICROSOFT
      ↓
ASP.NET Backend creates authorization request/state
      ↓
Browser redirected to Microsoft identity/authorization endpoint
      ↓
User signs in / approves required access
      ↓
Microsoft callback to SILA ME backend
      ↓
Backend validates state/callback
      ↓
Backend validates target SharePoint site / document location
      ↓
Store validated metadata
      ↓
Redirect back to SILA ME Cloud
      ↓
Status = CONNECTED
      ↓
Display validated SharePoint URL.

Do NOT implement Microsoft authentication purely in React.
